## 2. Working architecture selected for the next iteration

The [Hapa Connectivity v0.1 contract](../protocols/hapa-connectivity-v0.1.md) and [conformance catalog](../protocols/hapa-connectivity-v0.1-conformance.json) establish the shared boundary. These are proposed design interfaces, not a shipped SDK or registered Protocol Card.

Share identity/contact evidence, local provider adoption, authenticated connection lifecycle, scoped record replication, bounded ephemeral presence, verified blob retrieval and diagnostics. Keep game rules, seats, deterministic agreement and result evidence in the Versus application adapter. Collaborative-document merge/undo/membership behavior belongs to its own application adapter.

Versus is the first implementation owner for hardening the existing native connection primitives. A second application validates those boundaries before extraction into a versioned package. Do not copy the entire Versus runtime into each app or depend on an unpublished package. Publish compatible changes through explicit versions/digests and conformance evidence. Preserve `hv1`, existing signatures and archived records; any future shared identity linking needs an explicit owner/delegation contract, never silent secret copying.

The public contract contains only generic design. Keep private application source, findings, local histories and secrets in their appropriate owner repositories. Runtime observations, provider declarations, adoption decisions, application records and reward/entitlement claims remain different records.

2. The reviewing assistant independently checks the candidate, preserves accepted corrections, publishes findings and the next tasking, and explains what readiness claim the evidence supports.
3. CJ retains product direction, human playtest/aesthetic acceptance and Done. Technical reports do not assert those decisions on CJ's behalf.
